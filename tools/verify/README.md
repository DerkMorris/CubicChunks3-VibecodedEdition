# Port verification

From the repository root, build the packaged mod using JDK 25. The patched Core sources are included under libraries/cubicchunks-core.

```powershell
./gradlew.bat build
./tools/verify/verify-core.ps1 -JavaHome $env:JAVA_HOME
```

`verify-core.ps1` runs the existing 12 tests in `CloPosTest` and `MinecraftHeaderLinkageTest` against the linked Core JAR extracted from the packaged mod and the real Minecraft version declared in `gradle.properties` (26.3 for this port). It compiles and links the test bytecode separately; no Core implementation is replaced by test headers or mocks. It does not launch Gradle or modify Core sources or build files.

The script uses `GRADLE_USER_HOME`, falling back to the current user's `.gradle` directory. Override it with `-GradleUserHome <path>` when needed. `-ModJar`, `-CoreJar`, and `-MinecraftJar` override the packaged mod, unlinked Core build, and Loom merged Minecraft artifact paths. Dependencies are resolved by exact versions from the populated Gradle cache. The JUnit console is pinned to 1.13.4 and downloaded from Maven Central only when not already cached; `-Offline` prevents that download.

PowerShell 5.1 or newer is supported on Windows. PowerShell 7 can run the same script on other platforms; use `./gradlew build` for the initial build there. `-JavaHome` must identify a JDK with `java`, `javac`, and `jar`. Paths containing spaces are supported through Java argument files. Each run writes a separate directory under `tools/verify/build/core-headers-*/`, containing the linked test JAR, the extracted production Core JAR, command argument files, and JUnit XML reports.

The main `./gradlew.bat test` suite runs through Fabric Loader JUnit with the actual mixins and DASM transforms. Its two generation integration fixtures use scoped in-memory cube NBT storage attached only to each fixture's `ChunkMap`; column storage and the real scheduler/generation stages still run normally. Those two fixtures do not validate production persistence. Separate IntegrationTestCubePersistence, entity and POI tests use the real file store, including delayed-worker barriers for asynchronous saves, dirty-state races, unload retention and disk failures. The optional worldSmoke source set also exercises a real client/integrated server and fresh-process save/reopen; use the -PsmokeAsyncSaves flag for the asynchronous-save run. A test-only crash-report hook preserves the first original exception as an assertion cause before Windows hardware diagnostics run, and event-loop polling fails a fixture after 60 seconds. These hooks are packaged only with the test sources and are inactive outside a generation fixture.

Automatic-light tests compare both layers against the native 26.3 solver, exercise large positive/negative heights, stale background work, per-cube packet epochs, and saved unloaded roofs. To run real client/server lighting checks, use `-PworldSmoke -PsmokeWorld=<fresh-name> -PsmokeLighting runWorldSmoke`, then repeat with `-PsmokeReopen`. The default sample height is +/-32 million: this checks numeric brightness and transport, while the known packed-render-section limitation still prevents geometry there. Add `-PsmokeLightHeight=32000 -PsmokeLightRender` with a different fresh name to require visible render sections at every stage. Probe classes/configuration are excluded from the packaged JAR.

Add `-PsmokeLightContinuity` to that fresh-world lighting run to check the client's scalar and all eight section light layers every client tick during roof construction. A development-only Mixin pauses client light-queue application for two seconds to make the pending interval observable without blocking either game thread. The unchanged lamp must stay lit even while current light readiness is revoked, and the run must observe at least one pending interval. Unit and transformed-cache tests also verify that stale callbacks cannot replace the display, actual darkness still applies, eviction clears retained light, and server reads retain strict current-data semantics.

The lighting probe also places and breaks an opaque block next to an underground lamp, requires tracked neighboring cubes to finish relighting, and inspects first cube packets for exact light installed before rendering. It prints `serverLightMs`, `clientLightMs`, and total `latencyMs` through mesh readiness, sampled on client ticks. New-region timings include generation/loading and are not solver-only timings. Omit `-PsmokeLightContinuity` when measuring latency; its intentional two-second queue delay is solely a display regression check. The scheduling tests use controlled executors and work counts rather than flaky wall-clock assertions.

For client light prediction, run `-PworldSmoke -PsmokeWorld=<fresh-name> -PsmokeLightPrediction -PsmokeLightHeight=32000 runWorldSmoke`. This separate probe builds a grass/dirt platform, breaks 18 blocks with native creative actions across a vertical cube boundary, and holds server light-queue application until two seconds after the last break. Each newly opened cell must be air with sky level 15 before the action returns and on every following tick. The probe captures `run/world-smoke/screenshots/light-prediction-dig.png`, then requires server confirmation and current client light readiness before exiting. `maxBreakMicros` includes the whole native break call, not just propagation. Component tests cover both height signs, horizontal and vertical boundaries, unlit caves, authoritative correction, immutable render publications, eviction, and interleaved full snapshots with pending block/entity predictions.

For decreasing client light, use `-PworldSmoke -PsmokeWorld=<fresh-name> -PsmokeLightDecrease -PsmokeLightHeight=32000 runWorldSmoke`; height `96` exercises the same scene at ordinary altitude. The probe builds a room crossing a vertical cube boundary and performs five native creative actions: close the skylight, remove each of two torches, place a new torch, and reopen the skylight. Every action must update light immediately, retain the other source's contribution, and remain correct every tick during a two-second client light-queue delay. Each phase finishes only after authoritative server confirmation and current client readiness. It saves `run/world-smoke/screenshots/light-prediction-decrease-<height>.png` after the first torch is removed. `maxActionMicros` measures the entire native action plus its immediate assertions. Tests additionally compare every cell in both layers against a fresh vanilla engine through water/slab changes and verify that exceeding the work budget never publishes a half-cleared display.

For client entity ticking, use `-PworldSmoke -PsmokeWorld=<fresh-name> -PsmokeMobTicks runWorldSmoke` with no other probe flags. This creates a Creative/Normal world and runs scenes at Y=96 and Y=32,000. Six mobs (pig, cow, zombie, enderman, bat and cod) follow controlled server positions through ordinary entity packets; a seventh pig runs a native goal and navigation. The probe checks native client tick membership, interpolation, walking animation, damage countdown expiry, a real player attack confirmed on the server, and final client/server position agreement after movement settles. Client and server tick counts are measured independently. It requires `CC_MOB_TICK_COMPLETE`, saves mid-run and completed screenshots as `run/world-smoke/screenshots/mob-ticks-<height>[-complete].png`, then shuts down normally. `TestClientCubeEntityTicking` separately covers spawn/load order, movement across aliased full-height sections, unloading/eviction, view changes, freeze/passenger rules, always-ticking entities and ordinary column delegation. The probe uses compiled production code without `IS_IN_TEST` and is excluded from the release JAR; remote multiplayer and all specialized AI behaviors are outside its coverage.

Run `-PworldSmoke -PsmokeBiomes -PsmokeWorld=<fresh-name> runWorldSmoke` to verify the biome pipeline with a real client and integrated server. It samples a forest and ocean using the world biome source, checks logs and water on both sides, and visits a cave beneath the forest. Add `-PsmokeReopen` to repeat on the saved world.
